# 读者

没有读者，就没有价值。先写清这篇给谁，再决定能用哪些词、问答栏问谁。

## 点名

答三句，写不出来就先问用户一次：

1. **谁在读** — 使用者、集成者、编写者、运维、贡献者，或几类并存。
2. **在哪读** — 产品页、教程、API、FAQ、内部设计、发版说明……以文件为准，不要默认 README。
3. **读完要能做什么** — 跑起来、接进去、写一份、排障。做不到，这篇对这类读者没有价值。

对外页按会用产品、但不读源码的人写。贡献者页才允许内部词。同一仓库可以有几类表面，不要用贡献者词写给普通人看的栏。

## 黑话测试

对每个关键词问：这类读者没读过本仓库、也不是本项目贡献者时，是否还认得。

**换掉：**

- 仓内黑话、项目自造复合词、贡献者切口。
- 读者打不开的内部文件名当口号（对外把实现文件名写成卖点）。
- 机制名顶替读者要买的那句话（「我们有插件」通常不是读者问题）。

**可留：**

- 家喻户晓且不是本项目切口的词（如许多产品里的 Agent）。
- 这篇读者已经在用的产品名、格式名、CLI 名。
- 编写者文档里的实现文件名（他们就是来改这些文件的 ）。

主语要在：分享、复用、切换，必须写清对象。只有动词、没有对象，读者不知道你在卖什么。

## 问答栏

有 FAQ / Q&A 时走这一条，不另开一章。

- 每题先标读者类。一篇可以并用几类，不要混成一套假问题。
- 只留这类读者会真问出口的。把品类地板编成自问自答（没人会问的机制卫生）删掉。
- 答案写够：怎么用、写在哪、和相邻机制怎么接。展开后仍是一句是/否，不要占栏。
