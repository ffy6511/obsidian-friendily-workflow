# 反例（审查时对照）

这些是「看起来像文档、其实没给读者价值」的典型。对照用，不要当成某一产品的清单。

## 把品类地板放进特点栏

评测产品把「有评测脚本、过程跑完不算通过」写成第三张特点卡。同类评测默认都有打分。这是**默认需求**，进 FAQ 或删掉，不要占特点栏。

## 和「没有这件事的产品」从 0 比

「我们支持 Docker」对从不做隔离的聊天产品是 0/1，对 Harbor / Inspect 不是特点。比较对象必须是同一品类。

## 内部文件名当口号

对外介绍写成「换环境和 Agent 不用改 `run.py`」。读者不知道这个文件是什么。口号用读者的词；文件名留给编写者文档。

## 机制名顶替特色

特点卡标题叫「插件可插拔」。插件是做法。读者要的是：换 Agent 不必 fork 基座。做法进正文，超出预期的那句进特点栏。

## 只有动词、没有对象

「分享与复用」没有主语。别人的榜也分享分数。要写清分享的是 dataset、插件还是 Agent 配置，以及别人拿去能不能接着跑。

## 问答栏的假问题

「轨迹完整，是不是就算通过？」没有正常使用者会这样问。展开后一句「不算」更浪费耐心。问答只留真问题，答案要够用。

## 把贡献者架构导览当产品中段

Core 六格、槽位表、卫生项当 landing 的明星章节。贡献者文档可以有；给普通人看的中段要按三层对栏。
